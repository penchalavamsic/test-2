- **Network (1 test):** No POST/PUT/PATCH/DELETE during date and search operations (LIMAS-SUD-922).
- **Accessibility (3 tests):** Date value announcement after setting (LIMAS-SUD-923), search value announcement after filling (LIMAS-SUD-924), focus after date clearing (LIMAS-SUD-925).

**Verified behaviors:**
- Date input accepts future, past, and current dates without native HTML5 rejection.
- Each date change triggers exactly 1 GET to `/api/flicense/ex/{date}/{profileId}?page=0&size=5`; clearing the date triggers a GET with the application's default date.
- Search is entirely client-side — 0 API requests for fill, clear, Enter, or Escape.
- Search field clears on Escape; Enter has no special effect (no navigation, no request).
- Count text stays "loaded · total licenses" format, never switches to "matches" format.
- No-match empty state: "No matching floating licenses found" / "Try a different user ID, profile, hardware ID, or role."
- Default empty state: "No floating licenses found" / "No floating licenses match the selected expiration criteria."
- Combined date+search interactions are independent — clearing one never clears the other.
- Only GET requests are issued on `/api/flicense/`; no POST, PUT, PATCH, or DELETE.
- Focus remains on a reasonable element after date clearing.

**Blocked cases: 0.** All 38 cases are deterministic and supported by live UI observation.
